# Практична робота №5 — Flutter Widgets

## Тема

**Widgets and Components**

## Опис проєкту

Цей проєкт є результатом виконання практичної роботи №5 з дисципліни **«Програмування для мобільних платформ»**.

Метою роботи є практичне ознайомлення з побудовою інтерфейсу у Flutter, створенням власних `StatelessWidget` і `StatefulWidget`, використанням анімацій, централізованим керуванням станом та написанням автоматизованих тестів.

У межах практичної роботи створено демонстраційний застосунок із трьома основними екранами:

* головний екран із демонстрацією компонентів;
* екран товарів;
* екран профілю користувача.

Застосунок демонструє роботу багаторазово використовуваних Flutter-віджетів, взаємодію між екранами, централізований стан та адаптивне розташування елементів.

## Основні екрани

### Головний екран

Головний екран демонструє створені власні компоненти:

* `ProfileWidget`;
* `CustomButton`;
* `AnimatedCounter`.

Також із головного екрана доступна навігація до екрана товарів та профілю користувача.

### Екран товарів

Екран містить картки товарів із можливістю:

* перегляду назви, опису та ціни;
* перегляду зображення;
* збільшення зображення;
* додавання товару до кошика;
* додавання товару до обраного;
* видалення товару з обраного;
* використання горизонтального свайпу для керування обраним;
* перегляду актуальної кількості обраних товарів;
* перегляду актуальної кількості товарів у кошику.

На широких екранах товари відображаються у сітці з двома колонками, а на вузьких — вертикальним списком.

### Екран профілю

Екран профілю відображає дані поточного користувача та дозволяє редагувати:

* ім'я;
* електронну пошту.

Перед збереженням виконується перевірка введених даних. Некоректний email або порожнє ім'я не дозволяються.

## Власні віджети

### ProfileWidget

`ProfileWidget` — власний `StatelessWidget` для відображення інформації про користувача.

Віджет підтримує два режими:

* розгорнутий;
* компактний.

Також він приймає callback для обробки натискання кнопки редагування профілю.

### CustomButton

`CustomButton` — багатоцільовий `StatelessWidget` для створення кнопок із різними стилями.

Підтримуються стилі:

* `primary`;
* `secondary`;
* `danger`;
* `outline`.

Додатково реалізовано:

* іконки;
* callback `onPressed`;
* loading-стан;
* візуальне оформлення відповідно до обраного стилю.

### AnimatedCounter

`AnimatedCounter` — власний `StatefulWidget`, який демонструє роботу зі станом та анімаціями.

Містить:

* збільшення значення;
* зменшення значення;
* обмеження мінімального та максимального значення;
* анімацію зміни числа;
* анімацію кольору;
* плавну зміну прогресу;
* анімовані кнопки керування.

### ProductCard

`ProductCard` — `StatefulWidget` для відображення окремого товару.

Віджет реалізує:

* анімацію натискання;
* shimmer-анімацію під час завантаження зображення;
* обробку помилки завантаження зображення;
* додавання товару до кошика;
* роботу з обраним;
* горизонтальні свайпи;
* анімовану зміну іконки обраного;
* перегляд зображення;
* масштабування зображення.

## Керування станом

Для централізованого зберігання стану використовується клас:

```text
AppState extends ChangeNotifier
```

Він відповідає за:

* поточного користувача;
* список обраних товарів;
* кількість товарів у кошику.

Основні методи:

```text
setUser()
toggleFavorite()
addToCart()
removeFromCart()
clearCart()
```

Після зміни стану викликається:

```text
notifyListeners()
```

Для оновлення інтерфейсу використовується `AnimatedBuilder`.

Такий підхід дозволяє уникнути дублювання стану між окремими екранами та підтримувати єдине джерело актуальних даних.

## Архітектура

Проєкт розділено на декілька рівнів відповідно до їх призначення:

```text
Models
  ↓
AppState
  ↓
Screens
  ↓
Custom Widgets
```

`Models` містять структури даних застосунку.

`AppState` відповідає за спільний стан користувача, обраних товарів та кошика.

`Screens` формують основні сторінки застосунку.

`Widgets` містять повторно використовувані компоненти інтерфейсу.

Для детальнішого опису структури проєкту використовується файл:

```text
docs/architecture.md
```

Такий поділ спрощує підтримку проєкту, повторне використання компонентів та подальше розширення функціональності.

## Адаптивність

Для підтримки різних розмірів екрана в застосунку використовується адаптивне компонування.

На головному та профільному екранах основний вміст обмежується максимальною шириною та розміщується всередині прокручуваного контейнера.

На екрані товарів використовується різне компонування залежно від ширини вікна:

* широкий екран — сітка з двома колонками;
* вузький екран — вертикальний список.

Також для окремих компонентів використовується `LayoutBuilder`, що дозволяє змінювати розташування елементів залежно від доступної ширини.
