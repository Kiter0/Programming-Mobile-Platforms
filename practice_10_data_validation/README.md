# Практична робота №10.3
## Варіант 5 — Data Validation Layer

### 1. Опис проєкту

**Data Validation** — це мобільний застосунок, розроблений на Flutter, який демонструє реалізацію окремого рівня валідації та очищення даних перед їх збереженням у базі даних SQLite.

Застосунок дозволяє:
- Додавати користувачів із зазначенням імені, електронної пошти та номера телефону.
- Перевіряти правильність введених даних.
- Очищати дані від зайвих пробілів і непотрібних символів.
- Зберігати перевірені дані в локальній базі SQLite.
- Переглядати список збережених користувачів.
- Видаляти записи.
- Обробляти помилки валідації та роботи з базою даних.

### 2. Використані технології

- **Flutter** — розробка мобільного інтерфейсу.
- **Dart** — основна мова програмування.
- **SQLite** — локальне збереження даних.
- **sqflite** — взаємодія з SQLite.
- **path** — формування шляхів до файлу бази даних.
- **flutter_test** — написання та виконання автоматизованих тестів.

### 4. Основні компоненти

**User (`models/user.dart`)**

Модель користувача, яка містить ідентифікатор, ім'я, електронну пошту та номер телефону. Реалізовано перетворення об'єкта на Map і навпаки, а також метод `copyWith()`.

**UserValidator (`validators/user_validator.dart`)**

Відповідає за перевірку правильності введених даних:
- Перевірка імені та його довжини.
- Перевірка формату електронної пошти.
- Перевірка номера телефону.
- Загальна перевірка всіх полів користувача.

**UserSanitizer (`services/user_sanitizer.dart`)**

Виконує очищення даних перед валідацією:
- Видаляє зайві пробіли в імені.
- Переводить електронну пошту в нижній регістр.
- Видаляє пробіли та розділові символи з номера телефону.

**DatabaseHelper (`database/database_helper.dart`)**

Забезпечує створення та роботу з локальною базою SQLite. Реалізовано створення таблиці користувачів, додавання, отримання та видалення записів.

**UserRepository (`repositories/user_repository.dart`)**

Об'єднує роботу з моделлю, санітизацією, валідацією та базою даних. Перед збереженням дані очищуються та перевіряються. Для обробки помилок використовуються окремі класи винятків `UserValidationException` і `UserRepositoryException`.

**UserForm (`widgets/user_form.dart`)**

Віджет форми введення даних користувача з полями імені, електронної пошти та номера телефону.

**HomeScreen (`screens/home_screen.dart`)**

Головний екран застосунку. Забезпечує додавання користувачів, відображення збережених записів, їх видалення та показ повідомлень про помилки.

**main.dart**

Точка входу в застосунок. Ініціалізує Flutter та підключає репозиторій і головний екран.

### 5. Принцип роботи валідації

Обробка даних відбувається в такій послідовності:

1. Користувач вводить дані у форму.
2. `UserRepository` отримує введені значення.
3. `UserSanitizer` очищує та нормалізує дані.
4. `UserValidator` перевіряє їхню коректність.
5. Якщо помилок немає, створюється об'єкт `User`.
6. Перевірені дані зберігаються в SQLite.
7. Якщо виникає помилка, застосунок повертає відповідне повідомлення.

Некоректні дані не зберігаються в базі.


```bash

```

Запуск застосунку:

```bash
flutter run
```
