# Особистий щоденник — Flutter + SQLite

Мобільний застосунок для ведення особистого щоденника, створений із використанням Flutter та SQLite. Застосунок дозволяє створювати записи, фіксувати настрій, організовувати записи за допомогою тегів, переглядати історію в календарі та аналізувати власну активність.

## Про проєкт

Проєкт розроблено в межах практичної роботи № 9.2 «Робота з SQLite та Hive у Flutter».

**Варіант:** № 1 — Особистий щоденник із використанням SQLite.

Основна мета проєкту — реалізація мобільного застосунку для збереження особистих думок, подій і спогадів із можливістю їх подальшого пошуку, фільтрації та аналізу.

## Реалізований функціонал

### 1. Робота із записами

- Створення нових записів щоденника.
- Редагування наявних записів.
- Видалення записів.
- Збереження заголовка та тексту запису.
- Автоматичний підрахунок кількості слів.
- Збереження дати створення та оновлення запису.
- Додавання записів до обраного.

### 2. Відстеження настрою

Кожному запису можна призначити один із шести настроїв:

- Happy — щасливий.
- Excited — схвильований.
- Calm — спокійний.
- Neutral — нейтральний.
- Sad — сумний.
- Angry — роздратований.

Обраний настрій відображається в картці запису, календарі та статистиці.

### 3. Керування тегами

- Створення власних тегів.
- Редагування назв тегів.
- Вибір кольору з готової палітри.
- Видалення тегів.
- Відображення кількості записів, пов'язаних із кожним тегом.

Для зв'язку записів із тегами використовується відношення «багато до багатьох».

### 4. Пошук і фільтрація

- Пошук записів за заголовком і текстом.
- Фільтрація за настроєм.
- Фільтрація за тегом.
- Перегляд лише обраних записів.
- Групування записів за датою створення.

### 5. Календар

- Перегляд записів у форматі місячного календаря.
- Перемикання між місяцями.
- Вибір конкретного дня.
- Відображення кольорових позначок настрою для днів із записами.
- Перегляд записів вибраного дня.
- Перехід до поточної дати.

### 6. Статистика

- Загальна кількість записів.
- Загальна кількість написаних слів.
- Розподіл записів за настроями.
- Найчастіше використовувані теги.
- Статистика активності за місяцями.
- Визначення серії послідовних днів ведення щоденника.

## Структура бази даних SQLite

Застосунок використовує локальну базу даних `journal.db`, яка складається з трьох основних таблиць.

### Таблиця `journal_entries`

Зберігає записи щоденника.

| Поле | Тип | Опис |
|---|---|---|
| id | INTEGER | Первинний ключ |
| title | TEXT | Заголовок запису |
| content | TEXT | Текст запису |
| mood | TEXT | Обраний настрій |
| created_at | TEXT | Дата створення |
| updated_at | TEXT | Дата останнього оновлення |
| is_favorite | INTEGER | Статус обраного (0 або 1) |
| word_count | INTEGER | Кількість слів |

### Таблиця `tags`

Зберігає інформацію про теги.

| Поле | Тип | Опис |
|---|---|---|
| id | INTEGER | Первинний ключ |
| name | TEXT | Назва тегу |
| color | TEXT | Колір у HEX-форматі |
| created_at | TEXT | Дата створення |

### Таблиця `entry_tags`

Забезпечує зв'язок між записами та тегами.

| Поле | Тип | Опис |
|---|---|---|
| entry_id | INTEGER | Зовнішній ключ на `journal_entries` |
| tag_id | INTEGER | Зовнішній ключ на `tags` |

Обидва зовнішні ключі використовують `ON DELETE CASCADE`.

### Зв'язки між таблицями

- Один запис може мати декілька тегів.
- Один тег може бути пов'язаний із декількома записами.
- Таблиця `entry_tags` реалізує зв'язок «багато до багатьох».

### Індекси

Для оптимізації пошуку та фільтрації створено індекси:

- `idx_entries_created_at` — для дати створення записів.
- `idx_entries_mood` — для фільтрації за настроєм.
- `idx_tags_name` — для пошуку тегів за назвою.
- `idx_entry_tags_tag_id` — для пошуку зв'язків за ідентифікатором тегу.

## Робота з базою даних і SQL-запити

Уся логіка взаємодії з базою даних реалізована в класі `DatabaseHelper`, який використовує шаблон Singleton.

### CRUD-операції

У застосунку реалізовано основні операції:

- **INSERT** — додавання записів і тегів.
- **SELECT** — отримання записів, тегів і статистики.
- **UPDATE** — редагування записів і тегів.
- **DELETE** — видалення записів і тегів.

### Транзакції

Збереження запису разом із пов'язаними тегами виконується в межах однієї SQLite-транзакції.

Під час оновлення запису також використовується транзакція: оновлюється інформація про запис, видаляються старі зв'язки з тегами та створюються нові.

Це дозволяє підтримувати узгодженість даних.

### JOIN-запити

Для отримання записів разом із пов'язаними тегами використовуються SQL-з'єднання таблиць.

Це дозволяє завантажувати записи та їхні теги спільним запитом.

### Пошук записів

Для пошуку за заголовком або текстом використовується оператор `LIKE`:

```sql
SELECT *
FROM journal_entries
WHERE title LIKE ?
   OR content LIKE ?;
```

Параметри запиту містять символи `%`, які дозволяють знаходити збіги всередині тексту.

### Статистика за настроями

Для підрахунку кількості записів кожного настрою використовується `GROUP BY`:

```sql
SELECT mood, COUNT(*) AS total
FROM journal_entries
GROUP BY mood;
```

### Статистика за місяцями

Для групування записів за місяцями використовується функція SQLite `strftime`:

```sql
SELECT strftime('%Y-%m', created_at) AS month,
       COUNT(*) AS total
FROM journal_entries
GROUP BY month
ORDER BY month;
```

Додатково реалізовано підрахунок загальної кількості записів, найпопулярніших тегів, кількості слів і серії днів ведення щоденника.

## Проблеми та їх вирішення

**1. Організація зв'язків між записами та тегами**

Для реалізації зв'язку «багато до багатьох» створено проміжну таблицю `entry_tags`. Для збереження пов'язаних даних використовуються транзакції.

**2. Отримання записів разом із тегами**

Для завантаження записів і пов'язаних із ними тегів використовуються JOIN-запити.

**3. Оновлення статистики**

Статистичні показники обчислюються на основі актуальних даних SQLite після виконання операцій із записами.

**4. Асинхронна робота з базою даних**

Для виконання операцій із SQLite використовуються асинхронні методи Dart та оновлення стану інтерфейсу Flutter.
