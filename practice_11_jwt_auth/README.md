# Практична робота №11.2 JWT Authentication

## Тема роботи

Реалізація системи автентифікації та авторизації користувачів із використанням JWT, Dio та захищеного зберігання токенів у Flutter-застосунку.

## Мета роботи

Ознайомитися з принципами автентифікації та авторизації у мобільних застосунках, навчитися працювати з JWT-токенами, HTTP-запитами, перехоплювачами Dio, захищеним локальним сховищем та керуванням станом застосунку.

## Використані технології

- **Flutter** — розробка мобільного застосунку.
- **Dart** — основна мова програмування.
- **Dio** — виконання HTTP-запитів.
- **Provider** — керування станом авторизації.
- **flutter_secure_storage** — захищене зберігання токенів.
- **shared_preferences** — збереження налаштування Remember me та кешування даних.
- **http_mock_adapter** — імітація HTTP-відповідей під час тестування.
- **mocktail** — створення mock-об'єктів для тестів.
- **ReqRes API** — демонстраційний сервер для перевірки мережевої взаємодії.

## Реалізований функціонал

### 1. Автентифікація користувача

- Форма входу в обліковий запис.
- Форма реєстрації.
- Перевірка введених даних.
- Обробка помилок автентифікації.
- Отримання та збереження токена після успішного запиту.

### 2. Робота з токенами

- Збереження access token та refresh token у захищеному сховищі.
- Додавання Bearer-токена до авторизованих HTTP-запитів.
- Очищення токенів під час виходу з облікового запису.
- Реалізація механізму спроби оновлення токена після отримання HTTP 401.

### 3. Налаштування Remember me

- Можливість увімкнути або вимкнути запам'ятовування користувача.
- Автоматичне відновлення авторизованої сесії після перезапуску застосунку, якщо налаштування увімкнене.
- Очищення токенів після перезапуску, якщо запам'ятовування вимкнене.

### 4. Профіль користувача

- Завантаження інформації про користувача із сервера.
- Відображення імені, прізвища, електронної пошти та аватара.
- Редагування персональних даних.
- Надсилання PUT-запиту для оновлення профілю.
- Локальне кешування даних профілю.

### 5. Зміна пароля та вихід

- Форма введення нового пароля.
- Перевірка мінімальної довжини пароля.
- Надсилання запиту на зміну пароля.
- Підтвердження виходу з облікового запису.
- Видалення токенів і кешованого профілю під час виходу.

### 6. Обробка мережевих помилок

- Налаштування Dio з тайм-аутами підключення та отримання відповіді.
- Використання request та response interceptors.
- Централізована обробка DioException.
- Логування мережевих запитів у режимі налагодження.
- Перевірка коректності відповідей сервера.

## Особливості використання ReqRes API

У роботі використовується ReqRes як демонстраційний API. Він дозволяє перевірити HTTP-запити, отримання токена та обробку відповідей сервера, але має певні обмеження:

- Реєстрація та вхід є демонстраційними операціями, а не повноцінною системою облікових записів.
- API не забезпечує повноцінної видачі окремих access та refresh токенів.
- Endpoint для оновлення токена не підтримується, тому реальне оновлення токена через сервер не перевіряється.
- Операції оновлення профілю та зміни пароля демонструють надсилання запитів, але зміни не зберігаються на сервері.
- Після реєстрації та входу використовується один демонстраційний профіль користувача.

Ці обмеження пов'язані з можливостями демонстраційного API, а не з інтерфейсом застосунку.
